## main 发布条件

1. 合并代码不会自动把main变成codex的两库配置。当前main仍为chunks-v1，使用自己的317库；codex是f5正文库＋7704图片库。不得将codex数据库ID或空数据覆盖到main。
2. main需要同样的容量升级时，应单独准备main图片库及MAIN_MEDIA_D1_ID，再用既有迁移工具按发布时的新revision做dry-run和受版本保护的迁移。当前385只是本轮核查值，客户继续上传后必须重新读取，不能硬套。
3. 迁移前保留公开图文和私有内容历史备份；发布后核对ID、正文、媒体、私有历史和原密码/邀请码摘要，并给main巡检加对应图片库容量检查。保留旧媒体及旧快照，出问题按条目处理，不整库回退。
4. 本轮不开通R2、不创建main资源、不推main、不改正式口令/邀请码/API密钥。原地址.html入口继续有效。

## 仍需明确的边界

- 当前数百条图文容量充足；实际套餐尚未确认，按免费每库500MB保守规划。单库、账户总存储与每日读写额度分别受限；容量350MiB提前预警不是免费额度保证。大音视频继续使用已有链接。
- 浏览器内单包图片备份有64MiB预算；超出时导出文字与图片链接并明确说明缺图，完整媒体应使用已经验证的分文件维护备份。两者不能混称“完整图片备份”。
- 公开巡检不包含私有审计历史与外站媒体；私有迁移备份由维护人员另存。无服务器保存证据、无设备草稿/备份的历史内容不能凭空恢复。
- 早前两个基线缺条已有受邀管理员删除记录，是否误删尚未确认。本轮未自动恢复，也未通过修改基线消除该提醒；这与本轮软件修复验收分开记录。
- WebKit模拟和本机SQLite测试不等于真实iPhone/微信或线上峰值负载验收。公众号接入属于下一阶段发布验收；本轮不模拟扣费或把本地规模演练当真实云端额度。
