# 多人录入与草稿修复 · 2026-10-26

## 核对结果

- 正式库当前 revision 174，共 102 条自定义科普，包含“矮守围”。其中原有 26 条，10 月 26 日新增 76 条；当前 106 项操作历史里没有删除或回滚记录。不能把旧截图的 26 条当作当前云端总量，也不能据此证明所有未成功上传的旧稿都已恢复。
- 正式库只有一个有效邀请码，三个人可以共用，登录彼此不会使对方退出。本轮不更换密码、邀请码或 API 密钥，不复制两站数据库。
- 本机 ERR_CONNECTION_CLOSED 已由用户换 IP 恢复，用户明确要求暂停该问题，未修改系统网络。

## 已修复

1. 原先整库条件更新在三设备连续录入的隔离复现中，只保存了 15 条里的 7 条。普通保存现改为按条目提交前值摘要，服务端重新读取最新版本并在事务里合并；不会用旧列表替换整库。重复请求可识别已保存内容，不重复新增或提交。
2. 一条旧稿冲突曾阻断后续所有上传和云端读取。现只隔离冲突条目，其他新增仍可保存，也继续读取同事的新资料；冲突及本机内容随草稿持久化，后台重试不会强行覆盖云端。
3. 编辑表单保留打开时的版本，防止后台同步后将同事的新修改当作旧稿覆盖。冲突提供“使用云端”或“另存本机副本”，不要求丢弃整个资料库。
4. 后台原来没有随轮询刷新列表，旧条数可能一直留在界面。现自动更新非编辑列表，保留搜索和正在填写的表单，分别显示云端数量及待上传项。首次尚未读到云端时不以 0 条误导用户。
5. 科普表单输入和选图自动保存在本机，可通过“找回草稿”恢复；明确显示本机保存与上传状态。手动读取云端时先归档待上传内容，不删除唯一草稿。
6. 网关 HTML、断连等曾被统一误报“未部署”。现作临时服务异常处理，安全的读取和按条目保存可重试，保留草稿。部署切换中的接口版本差异有单独提示。
7. 普通保存只上传变动条目，返回小体积确认及归属字段，不再回传已上传图片。版本落后时在后台读取其他更新，读取期间不冒充已加载全库。约 8.35 MB 的 102 条真实资料副本在隔离库中新增一条纯文字记录，上传请求不足 1 KB。服务端只复制变动记录，避免反复序列化回滚大图。
8. 精简后台、上传、备份、问答设置及首页提示，移除“秒级同步”“智能压缩保真”等承诺。历史资料正文保留。
