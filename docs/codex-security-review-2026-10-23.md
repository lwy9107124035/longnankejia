此文记录整改前的历史审查。后续修复与验证见 [整改验收记录](codex-security-fixes-2026-10-23.md)；下文原始复现结论仅针对审查时提交。

审查日期：2026-10-23（Asia/Shanghai）。审查对象：`codex` 的 `7405e03`，核心修复代码来自 `f56f7b6`。与当时 `main` 的 `bce4c6b` 对比，应用实现相同，仅发布记录不同，因此下面的实现风险也需要纳入正式站整改。

本轮只新增审查材料和本地复现工具，没有修复产品实现、提交或推送分支，没有在真实站点注入内容、改密、上传或删除记录。攻击验证全部使用本机隔离 SQLite、合成账号及测试口令；在线仅执行公开页面和接口的只读检查。

### F01：存储型脚本注入与超管操作劫持

位置：[正文格式化](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/ui.js:13>)、[卡片 HTML 拼接](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/ui.js:736>)、[详情插入](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/ui.js:965>)、[线上 CSP](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/_headers:9>)。

- 前提：攻击者有一个有效协管员账号，并使超级管理员浏览到受影响内容。不是匿名任意写入，也不是服务器远程代码执行。
- 复现：协管员经真实接口保存带事件处理器的卡片图标；超管页面同步后触发事件，使用超管当前会话调用改密接口。新指定的合成口令随后可登录。另以含 `<p>` 的详情正文单独确认事件脚本执行。
- 根因：图标、名称和标签直接拼接进 `innerHTML`；“检测到 HTML 就原样返回”只是格式选择，不是 HTML 安全净化。线上 CSP 明确允许 `unsafe-inline`，不能阻止这些事件处理器。
- 修复：纯文本字段用 `textContent`；富文本使用维护中的 HTML 净化器及标签/属性/URL 白名单，覆盖后台预览和前台所有入口。移除危险事件属性并逐步收紧 CSP；敏感改密操作可增加重新验证当前凭据，不能仅依赖现有会话。OWASP 建议对必须保留的 HTML 做净化，不能把输出原始 HTML 当作安全措施。[OWASP XSS 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)
- 验收：协管员所有文本、图标、正文和媒体字段的事件/脚本均不执行；合法段落、换行、强调格式仍正确；超管密码保持原值。

### F02：共享 IndexedDB 的草稿覆盖

位置：[读取统一 current 快照](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:175>)、[写入统一 current 快照](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:199>)。

- 复现：同一浏览器、同一站点打开 A/B 两个标签页并登录；令两页管理接口离线；A 新增草稿 A 并等待本地保存，B 新增草稿 B 并等待保存；保持接口离线，刷新 A。A 恢复成草稿 B，草稿 A 已不在本机快照或云端。
- 根因：每页有独立的内存、generation 和 pending，但整个来源只使用一条 IndexedDB `current` 记录。事务保证单次写入完整，不能解决不同标签页互相替换快照。IndexedDB 以来源隔离，不能把它当成每个标签页独占的存储。[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)
- 修复：缓存与待上传操作分开存储；按标签页/草稿/操作 ID 保存未确认编辑，使用事务版本检查和跨标签页协调；已保存的旧草稿必须保留到云端确认或用户显式丢弃。
- 验收：双标签页、不同账号、先后及同时离线编辑，关闭任一页后两份草稿均可找回并分别合并；不能只测试不同浏览器上下文。

### F03：重新加载云端期间的编辑被覆盖

位置：[reloadCloudContent](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:398>)。

- 复现：形成同条编辑冲突；确认重新加载，暂停该 GET 响应；在等待过程中新增一张卡片，再放行响应。新卡片从工作内容和备份数据中消失，云端也没有该卡片，pending 已为 false。
- 根因：读取完成后无条件清空 pending 并应用响应，没有比较发起时与完成时的 generation。用户确认丢弃旧草稿不等于确认丢弃随后刚输入的内容。
- 修复：记录发起时的编辑代数和草稿快照；期间有新编辑时停止覆盖并保留两份版本，或明确锁定所有编辑及保存入口直到重新加载结束。
- 验收：慢网下覆盖新增、编辑、删除、导入以及点击取消/退出等组合；确认后产生的编辑必须仍可恢复。

### F04：无效记录可持久化并使公开页面报错

位置：[contentPayload](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/functions/api/admin/sync.js:163>)、[完整包导入](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:1074>)、[渲染读取 id](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/ui.js:489>)。

- 复现：同步包的 `kepuCustom` 设为 `[null]`，其余字段保持合法，服务端返回 200。公开 GET 随后仍返回 null，真实浏览器渲染报 `Cannot read properties of null (reading 'id')`。
- 根因：只检查外层是数组/对象，没有验证每条记录、字段类型和必填项；前端也假设每条卡片一定是对象。完整包导入可带入同类坏数据。
- 修复：在服务器验证各模块记录结构、ID、字段类型和长度，拒绝坏包且保持旧版本不变；前端对历史坏记录隔离展示并报告具体条目，不让一条坏记录使整个列表失败。
- 验收：null、数字、数组、缺 ID、对象类型的名称/正文、非法编辑映射等均返回 400；原云端内容、revision 不变；历史坏数据有恢复办法。

### F05：审核日志泄漏有效邀请码

位置：[回滚日志](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:536>)、[剔除日志](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:682>)、[向全部登录用户返回日志](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/functions/api/admin/sync.js:184>)。

- 复现：给甲/乙签发不同邀请；甲录入一项，超管驳回；乙通过登录后的同步接口获得包含甲完整邀请码的审计记录。该码仍能登录为甲，HTTP 200。
- 根因：日志 detail 拼接 `tokCode`，而邀请码本身就是登录凭据；所有受邀用户都可经接口读取 auditLogs，隐藏后台按钮不能保护接口数据。相关通知及备份还会扩大凭据落盘范围。
- 修复：日志只保留不具备登录能力的邀请 ID/脱敏标识，日志读取按权限及相关用户过滤；清理历史日志/导出内容中的凭据，并评估换发曾暴露且仍有效的邀请。OWASP 将访问令牌和认证秘密列为不应直接记录的数据。[OWASP 日志指南](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)
- 验收：任何角色的同步、通知、备份和日志中都不能出现完整邀请凭据；乙不能获得甲的可用登录码。匿名公开 GET 未直接返回 tokens 列表，不代表此路径安全。

### F06：重复 ID 使一次删除影响多个记录

位置：[服务端包校验](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/functions/api/admin/sync.js:163>)、[按 ID 删除卡片](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:950>)。

- 复现：保存两个同 ID、不同名称的卡片，接口返回 200。删除其中一个 ID 后，两条同时被移除，数量 2→0。
- 区别：此前“列表被重复合并”的问题已修复；本项是数据本身含重复 ID，不能据此断言此前所有重复显示仍未修复。
- 修复：服务器拒绝模块内重复 ID、自定义与内置保留 ID 冲突；导入先预检并明确提示处理方式，不在合并时静默折叠。
- 验收：正常新增、导入、恢复、跨端合并均保持 ID 唯一；删除只影响一条目标记录。

### F07：审计与内容归属可由协管员伪造

位置：[整包更新权限判断](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/functions/api/admin/sync.js:202>)。

- 复现：协管员提交任意 auditLogs，将 actor 写成“超级管理员”，将新卡片 creatorTokenId 写成别人；保持模型/工作流配置不变，服务端返回 200。超管按真正的协管员令牌回滚时移除 0 条，伪造归属的记录仍存在。
- 根因：服务器只限制配置字段差异，直接信任客户端传入的日志、操作者和创建者信息。实际会话中的 user/tokenId 没有用于建立不可伪造的操作归属。
- 修复：服务器根据已验证会话生成 actor、creatorTokenId、时间和操作日志；不接受客户端整体替换审计历史。对于编辑或删除他人条目的权限，应先明确产品规则，再做服务端授权。
- 验收：协管员不能伪造超管操作、清除/重写历史或转移创建归属；日志能对应服务器实际写入。

### F08：回滚只清理新增项，遗漏内置编辑和删除

位置：[rollbackTokenChanges](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:504>)、[内置知识编辑](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:820>)、[删除记录](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:841>)。

- 复现：正常协管员修改内置甲、删除内置乙，不伪造任何信息；超管执行该令牌“全部修改”回滚。返回移除 0 条，甲仍是修改稿，乙仍不可见。
- 根因：回滚只筛选 custom 数组，没有记录及恢复 edited/deleted 中的操作者、旧值和操作顺序。
- 修复：用服务端版本化操作记录表达新增、编辑、删除及撤销；若暂时只支持撤回新增，界面必须如实说明，不能称全部修改已回滚。
- 验收：覆盖三个模块及新增/编辑/删除；多位编辑先后修改同一项时，撤销不能覆盖其他人的后续合法编辑。

### F09：会话写失败后回退仍选择旧会话

位置：[readSession/writeSession](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:61>)。

- 复现：存储中留有一个已失效的旧会话，模拟 sessionStorage 读取正常但写入抛配额错误；用正确密码登录。服务器返回成功，但下一次同步仍使用旧 bearer，随后清除本机登录状态。
- 根因：新会话已放入 memorySession，但 readSession 优先读取仍存在的旧存储值；仅测试“读取和写入同时被禁用”不能覆盖此情况。
- 修复：当前页面最新内存会话优先；记录写失败并使用明确降级，不把旧落盘值覆盖新认证结果。
- 验收：分别覆盖只写失败、只读失败、旧值损坏、旧会话撤销、刷新和独立退出；正确登录后当前页面应能继续管理。

### F10：审核反馈不会送达另一设备

位置：[同步字段列表](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:133>)、[本地通知写入](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/store.js:711>)。

- 复现：受邀者设备录入一项，超管在另一设备剔除并填写理由。内容已从云端删除，超管设备通知数为 1，受邀者同步后通知数仍为 0。
- 根因：通知只写管理员本机 localStorage，未纳入云端通知数据；用户可能只看到资料消失，不知道审核原因。
- 修复：通知由服务器创建并按接收人提供，已读状态跨设备持久化，通知只使用非凭据 ID。
- 验收：管理员和受邀者使用不同设备/浏览器，驳回理由能送达，刷新及已读状态一致。

### F11：未在读取过程中限制匿名请求体

位置：[先 request.text 再限长](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/functions/api/admin/sync.js:267>)；已有可参考的[流式受限读取](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/functions/_lib/siliconflow.js:129>)。

- 复现：隔离后端收到没有 Authorization、没有 Content-Length 的 32 MiB 流，完整读取 33,554,432 bytes 后，才按 16 MiB 限制返回 413。
- 影响边界：已证明超限内容先占用读取/解码资源，**没有进行线上内存耗尽或并发压测**，不能把本项描述成已经让 Cloudflare 崩溃。
- 修复：按实际读取字节数提前 cancel，并校验声明长度；登录采用较小的请求预算，大上传按鉴权及内容限额处理，避免认证前的大额资源消耗。复用现有有界读取能力，避免两套接口保护不一致。
- 验收：有/无/伪造 Content-Length、分块传输及中断请求；超限应在达到预算后停止继续拉取。

### F12：正常压缩 DOCX 无法导入

位置：[parseDocxToDrafts](<C:/Users/lwy/OneDrive/Desktop/新文科大赛/js/admin.js:1510>)。

- 复现：生成合法 ZIP_DEFLATED 的 DOCX，校验 ZIP 完整且 word/document.xml 确实包含足够长的中文正文；通过真实文件选择器上传，系统提示“Word 文档解析未提取到文字”，没有草稿。
- 根因：把整个 ZIP 二进制直接当 UTF-8 文本，再正则查 `<w:t>`，没有读取压缩包内的 document.xml。Microsoft 的格式说明也将正文说明为 ZIP 包内的 WordprocessingML 部件。[Microsoft WordprocessingML 结构](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document)
- 修复：使用可靠 ZIP/Word 解析实现，正确处理段落、实体、表格及解压大小限制；解析失败不能覆盖现有待导入内容。
- 验收：Word/WPS 生成的普通压缩文档、中文、表格、换行、空文档和损坏包；正文完整提取并能经草稿确认后入库。
