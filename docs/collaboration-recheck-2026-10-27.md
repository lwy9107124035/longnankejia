# 2026-10-27 独立复审

复审起点为已发布的 `9b674d6`。原有 111 项 Node 测试通过，但新增对抗测试仍发现边界问题，不能沿用“所有情况都已修好”的结论。以下复现只在隔离 SQLite/Chromium 进行，没有对客户资料注入、改密或执行破坏测试。

| 编号 | 确认问题 | 原因和修复 | 证据 |
|---|---|---|---|
| R01 / P1 | 复制标签页可能删掉原页面后来新增的离线草稿 | sessionStorage 的草稿指针会复制，旧逻辑直接删原指针；现在只在原快照版本未变时清理 | 修复前 Node 探针失败；修复后降级存储与真实 IndexedDB 均通过 |
| R02 / P1 | 已有发布缓存时，旧版未上传资料可能被跳过 | 初始化优先读取 IndexedDB 当前缓存；现在旧版待上传内容单独备份，优先恢复未上传副本，保留不同页面的两份草稿 | 真实浏览器“旧 localStorage + 现有 IndexedDB 缓存”修复前失败、修复后通过 |
| R03 / P1 | IndexedDB 暂不可用及恢复可用时，可能跳过降级草稿 | 仅“无 indexedDB 对象”走恢复，打开失败未走；恢复可用后又只查数据库。现初始化与找回草稿同时检查两种存储、按时间选择副本，清理仍核对快照版本 | open 抛错和“失败→恢复可用”两种真实浏览器场景均验证，后者修复前明确失败 |
| R04 / P1 | 编辑期间被同事删除的条目，可能变成不可见的覆盖记录或丢掉表单修改 | 自定义 ID 不存在后错误走内置覆盖路径；现按打开时的条目类型和原值保留，提交返回删除冲突，云端删除不被自动撤销 | 科普/知识两项修复前失败；修复后原云端为空、本机草稿仍在 |
| R05 / P1 | 旧版整库接口可用“只改归属字段”篡改创建者 | 元数据校正后判断正文相同就跳过赋值，留下原始伪造值；现无正文变化也写回服务端校正后的归属，不复制未变大图 | 旧接口只改 creator 字段的探针修复前失败、修复后通过 |
| R06 / P2 | 旧请求迟到的失效/退出响应可清除刚建立的新登录 | 清会话未核对请求使用的 bearer；现只清理对应旧会话 | 延迟失效探针修复前失败；失效与退出两路径现均通过 |
| R07 / P2 | 知识库保存未等服务器确认就关闭表单 | 页面保存逻辑与科普不一致；现等待确认、失败保留表单，并共用自动表单草稿和恢复逻辑 | 浏览器断网上传失败留表单、刷新找回标题正文通过 |
| R08 / P1 | 本机备份不可用时“读取云端”可能丢掉唯一内存草稿 | 未检查 persistState 的失败返回；现禁止切换/覆盖并要求先导出 | 存储完全禁用的修复前探针失败，新增拒绝丢弃断言 |
