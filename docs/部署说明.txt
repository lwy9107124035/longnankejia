龙南客家非遗数字助手 — 部署指南
==================================

当前方案：Git 推送 → Cloudflare Pages 自动部署（免费，不计 credits）
          GitHub Pages 作镜像同时上线；Netlify 降为只手动的备用宿主

为什么不用 Netlify：它 2025 年起按 credits 计费，本账号免费额度用完且未绑卡，之后
          任何新的生产部署都会被挡（现网仍在服务上一次成功的部署，网址不丢）。
为什么不只用 GitHub Pages：本机的 HTTPS 加速器对 github.io 没有路由，Chrome 打开会
          卡在 three.min.js 上（直连反而 0.9 秒）。*.pages.dev 走代理和直连都通。

首次配置（都已做好，重建账号时照此再来一遍）
--------------------------------------------
1. Cloudflare：装 wrangler（npm i -g wrangler --registry=https://registry.npmmirror.com），
   `wrangler login` 走一次浏览器授权；建两个 Pages 项目
     wrangler pages project create longnankejia      --production-branch main
     wrangler pages project create longnankejia-dev  --production-branch dev
2. Cloudflare 控制台 profile/api-tokens → Create Custom Token，权限只给
   `Account → Cloudflare Pages → Edit`（别用 Edit Cloudflare Workers 模板，它连带 13 项权限）
3. GitHub 仓库 Secrets 四项：
     SILICONFLOW_API_KEY   大模型密钥（只有生产那份会注入）
     CLOUDFLARE_API_TOKEN  上一步的令牌
     CLOUDFLARE_ACCOUNT_ID 账号 ID
     NETLIFY_AUTH_TOKEN / NETLIFY_SITE_ID  备用宿主用
4. GitHub Settings → Pages → Source 选 GitHub Actions（镜像那条通道要）


日常更新
--------
  git add -A
  git commit -m "改了什么"
  git push origin main

约 30 秒生效。进度：Actions → “Deploy to Cloudflare Pages” 与 “Deploy to GitHub Pages”。
注意 dev 的自动更新要等 dev 分支同步过 main（工作流文件只在 main 上，GitHub 读的是
被 push 那个 ref 里的工作流），在那之前 dev 靠每小时定时从 main 侧带出来。


发布内容
--------
.github/workflows/cf-pages.yml（Cloudflare）与 pages.yml（GitHub Pages 镜像）都只上线
页面真正加载的东西：

  index.html、css/、js/、assets/avatar、assets/pdf-imgs、assets/textures

docs/（比赛通知与简历）、tests/、scripts/、data/、assets/source/ 不上线。
以前 Netlify 的 publish = "." 会把这些一起推到公网，实测能直接下载到
tests/badge-template.npy 和 scripts/ 下的脚本，所以换成白名单。

dev 预览那份刻意不注入 API Key，页面按设计回落到本地知识库引擎；预览站是
另一个公开域名，不该再带一份线上密钥（tests/check_static.py 会守这条）。


入口二维码
----------
页面上的码跟随当前网址：部署到哪儿就扫出哪儿，不用改配置。
印展板用的成品图取自配置里的永久地址，换正式域名时改这一行再重跑：

  js/config.js  →  app.canonicalUrl
  python scripts/make_entry_qr_png.py     # 生成 docs/入口二维码.png，写完自检解码

测试会核对成品图与 canonicalUrl 一致，脱节直接 FAIL。
