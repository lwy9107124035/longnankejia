==================================

Cloudflare Pages 是线上入口，GitHub Pages 只保留 main 与 doubao 的镜像；Netlify 是手动备用。
API 参数在 main、qcode、codex、doubao 四个分支保持一致。SiliconFlow API key 由 Cloudflare
Pages Functions 在服务端读取，不会写进静态 JS 或 GitHub Pages 镜像。

Cloudflare 与 GitHub Actions 配置
---------------------------------
Cloudflare Pages 项目及 secret 环境按分支对应：

  main          项目 longnankejia      production
  doubao        项目 longnankejia-dev  production
  qcode         项目 longnankejia-dev  preview
  codex         项目 longnankejia-dev  preview

GitHub Actions 仓库 Secrets：
  SILICONFLOW_API_KEY    SiliconFlow 服务端 API key
  CLOUDFLARE_API_TOKEN   仅授予 Account → Cloudflare Pages → Edit
  CLOUDFLARE_ACCOUNT_ID  Cloudflare 账户 ID
  NETLIFY_AUTH_TOKEN / NETLIFY_SITE_ID  备用宿主凭据（可选）

cf-pages.yml 使用固定 Wrangler 4.137.0，把 GitHub secret 通过 stdin 写入目标 Pages
环境的 secret binding，然后部署 Functions 与白名单静态文件。日志和浏览器资源里不会有
密钥。GitHub Pages 与手动 Netlify 工作流只生成空的 js/secrets.js；主镜像的 API 请求
走 main Cloudflare Pages Functions 代理。Pages Functions 的来源与分支限制由服务端代码执行。

GitHub Settings → Pages → Source 需选择 GitHub Actions。


日常修改与发布
--------------
先确认目标分支：

  git branch --show-current
  git status --short

3D 模型、素材与 v2 页面修改只进 codex。API 配置/代理和部署工作流要保持四分支一致时，
逐一检查并更新 main、qcode、codex、doubao，提交后只向核验过的精确分支推送。不要使用
`git push --all`、通配 refspec 或把 codex 的模型改动推到其他分支。豆包分支名是 doubao，
原分支 dev 已改名。

codex 分支部署在 Cloudflare 项目 longnankejia-dev 的 codex 预览别名；GitHub Pages 镜像
只由 main 工作流发布 main 与 doubao 内容，不会随 codex 推送更新。


静态发布范围
------------
.github/workflows/cf-pages.yml 与 pages.yml 只发布：

  index.html、css/、js/、assets/avatar、assets/pdf-imgs、assets/textures

docs/、tests/、scripts/、data/、assets/source/ 不上线。Netlify 备用仍使用受限入口，且
生成空的浏览器密钥文件。


入口二维码
----------
页面二维码跟随当前网址。展板成品图使用 js/config.js 的 app.canonicalUrl：

  python scripts/make_entry_qr_png.py

该命令生成 docs/入口二维码.png 并自检解码。

备用：Netlify
------------
站点 https://prismatic-syrniki-1e0e96.netlify.app 仍提供上一次成功的部署。额度可用后，
